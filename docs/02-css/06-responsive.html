Module 2 · CSS

Responsive

Un site web, c'est fait pour être vu sur un téléphone, une tablette, un ordinateur, une TV… On n'a pas le choix : il doit s'adapter. Aujourd'hui, on apprend à construire des pages qui fonctionnent partout.

1 Le problème : un design figé

Une page conçue pour un écran de 1400px de large va casser sur un téléphone de 375px. Soit elle déborde (scroll horizontal), soit le texte est minuscule, soit les éléments se chevauchent.

❌ Sans responsive
LogoAccueilBlogContactÀ propos
Un long paragraphe qui ne s'adapte pas du tout à la largeur de l'écran et qui déborde…

Tout s'entasse, le texte sort de l'écran.

✅ Avec responsive
Logo☰
Un paragraphe qui s'adapte à la largeur disponible.

Le menu devient un burger, le texte respire.

Le chiffre qui change tout Depuis 2016, plus de 50 % du trafic web mondial vient du mobile. Aujourd'hui c'est ~60 %. Concevoir « pour desktop puis adapter » est une erreur. On conçoit d'abord pour mobile, puis on enrichit.

2 La balise meta viewport (indispensable)

Avant tout CSS, il y a une ligne HTML obligatoire dans le <head> de chaque page. Sans elle, rien ne fonctionne sur mobile. 

<meta name="viewport" content="width=device-width, initial-scale=1.0">
width=device-width

Le site doit faire la largeur réelle de l'appareil, pas 980px (valeur par défaut des vieux navigateurs mobiles).

initial-scale=1.0

Le niveau de zoom de départ : 1.0 = 100 %. Pas de zoom automatique qui rendrait tout bizarre.

Si tu oublies cette balise… Ton site s'affichera comme si l'écran faisait 980px de large, puis sera dézoomé pour rentrer dans le téléphone. Tout sera minuscule. C'est la toute première chose à vérifier quand « le responsive ne marche pas ».

3 Les media queries

Une media query (requête média) dit au navigateur : « applique ce CSS seulement si l'écran respecte cette condition ». La plus utilisée : la largeur de l'écran. 

/* Styles de base (par défaut, pour tous les écrans) */
.card {
  padding: 20px;
  font-size: 16px;
}

/* Quand l'écran est PLUS PETIT que 768px */
@media (max-width: 768px) {
  .card {
    padding: 12px;
    font-size: 14px;
  }
}

/* Quand l'écran est PLUS GRAND que 1200px */
@media (min-width: 1200px) {
  .card {
    padding: 32px;
  }
}
@media (max-width: 768px)

« Si l'écran fait 768px ou moins ». C'est la syntaxe desktop-first : on style pour grand écran, puis on corrige pour petit.

@media (min-width: 768px)

« Si l'écran fait 768px ou plus ». C'est la syntaxe mobile-first : on style pour petit écran, puis on enrichit pour grand.

D'autres conditions existent
  • @media (orientation: portrait) — écran vertical
  • @media (orientation: landscape) — écran horizontal
  • @media (prefers-color-scheme: dark) — mode sombre
  • @media print — pour l'impression
Mais dans la pratique, 95 % du temps on utilise min-width ou max-width.

4 Mobile-first vs Desktop-first

✅ Mobile-first (recommandé)

On écrit le CSS pour mobile, puis on enrichit avec min-width. 

/* Base : mobile */
.menu { display: none; }

/* Tablette et + */
@media (min-width: 768px) {
  .menu { display: flex; }
}
Desktop-first (historique)

On écrit le CSS pour desktop, puis on simplifie avec max-width. 

/* Base : desktop */
.menu { display: flex; }

/* Mobile et - */
@media (max-width: 767px) {
  .menu { display: none; }
}
Pourquoi mobile-first ?
  • On part du cas le plus contraint (petit écran) : ça force à simplifier.
  • Le code de base est plus léger (pas de surcharge inutile sur mobile).
  • Les styles par défaut d'un site sont souvent ceux du mobile, donc moins de CSS.
  • C'est la convention actuelle de l'industrie.

Un « breakpoint », c'est une largeur où on décide que le design doit changer. Il n'y a pas de règles absolues : ça dépend du contenu.

7 Les unités relatives

En responsive, on évite les px figés. On utilise des unités relatives qui s'adaptent à leur contexte.

Unité Relative à… Utilité
% La taille du parent Largeurs, hauteurs proportionnelles.
rem La taille de police racine (16px par défaut) Textes, marges, espacements. Recommandé.
em La taille de police du parent Rare, sauf cas très précis.
vw 1 % de la largeur du viewport Grands titres qui s'adaptent à l'écran.
vh 1 % de la hauteur du viewport Héros qui prennent tout l'écran.
vmin / vmax Le plus petit / plus grand côté Cas particuliers (formes carrées responsives).
La fonction magique : clamp() clamp(min, idéal, max) permet de définir une taille bornée. Idéal pour un titre qui doit être grand sur desktop, mais pas trop petit sur mobile :

font-size: clamp(1.2rem, 4vw, 2.5rem);

Lecture : jamais moins de 1.2rem, jamais plus de 2.5rem, et idéalement 4 % de la largeur de l'écran. Le navigateur choisit automatiquement.

8 Les images adaptatives

Deux règles simples à mettre dans ton reset CSS, et qui évitent 90 % des problèmes d'images sur mobile : 

img {
  max-width: 100%;    /* une image ne dépasse JAMAIS son conteneur */
  height: auto;       /* conserve les proportions quand elle rétrécit */
  display: block;     /* évite un petit espace fantôme sous l'image */
}
Le piège classique Sans max-width: 100%;, une image de 2000px de large casse la mise en page sur mobile : elle force le conteneur à faire 2000px, ce qui crée un scroll horizontal sur toute la page.

C'est l'erreur n°1 des sites mal responsive. Une seule ligne de CSS la règle. 
.img-demo {
  display: flex;
  gap: 12px;
  align-items: flex-start;
}
.img-demo figure {
  margin: 0;
  flex: 1;
  min-width: 0;   /* permet aux items flex de rétrécir sous leur contenu */
}
.img-demo img {
  max-width: 100%;
  height: auto;
  display: block;
  border-radius: 8px;
}
.img-demo figcaption {
  font-size: .78rem;
  color: var(--muted);
  margin-top: .4rem;
  text-align: center;
  font-family: 'JetBrains Mono', monospace;
}

↔ Rétrécis la fenêtre : les images rétrécissent mais ne débordent jamais.

9 Cas pratique : navbar qui devient burger

Le pattern le plus utilisé du web : sur desktop, le menu est horizontal. Sur mobile, il devient un simple burger (☰) qui déroule un menu. 

/* ===== BASE : MOBILE-FIRST ===== */

/* Le menu est caché par défaut */
.nav-links {
  display: none;
}

/* Le burger est visible */
.burger {
  display: block;
}

/* ===== TABLETTE ET PLUS ===== */
@media (min-width: 768px) {
  .nav-links {
    display: flex;
    gap: 16px;
  }
  .burger {
    display: none;
  }
}
<div class="nav">
  <span class="logo">MonSite</span>
  <div class="links">
    <a href="#">Accueil</a>
    <a href="#">Blog</a>
    <a href="#">Contact</a>
  </div>
  <button class="burger">☰</button>
</div>

10 Cas pratique : grille de cartes fluide

On a déjà vu ce pattern dans le cours Grid, mais c'est important de le reposer ici : la vraie manière d'avoir une grille responsive est souvent de ne pas utiliser de media query du tout. 

.grille {
  display: grid;
  gap: 16px;
  grid-template-columns: repeat(auto-fit, minmax(min(100%, 240px), 1fr));
}
Pourquoi c'est magique Le navigateur crée automatiquement autant de colonnes de 240px minimum que possible. Sur mobile → 1 colonne. Sur tablette → 2. Sur desktop → 3 ou 4. Sans écrire un seul @media.

11 Le test ultime : les DevTools

Tu n'as pas besoin d'un vrai téléphone pour tester ton site responsive. Les DevTools du navigateur ont un mode responsive intégré.

F12

Ouvre les DevTools.

Ctrl + Shift + M

Active le mode appareil (toggle device toolbar). Ton site se redessine dans un cadre.

Barre du haut

Tu peux choisir un appareil (iPhone, iPad, Galaxy…) ou définir une largeur personnalisée en tirant les bords.

Le test rapide à faire Ouvre n'importe quel site dans ton navigateur (Google, Wikipedia…), puis fais F12 + Ctrl+Shift+M. Regarde comment le site se transforme. C'est de cette manière que les développeurs testent leurs pages, tous les jours.

12 Ton reset CSS complet

Voici la version finale de ce que tu mettras au début de tous tes projets web à partir de maintenant : 

/* ============================================================
   Reset CSS — à mettre au début de chaque projet
   ============================================================ */

* {
  box-sizing: border-box;
  margin: 0;
  padding: 0;
}

html {
  /* Base de 1rem = 16px (défaut), utilisable partout */
  font-size: 100%;
}

body {
  font-family: system-ui, -apple-system, sans-serif;
  line-height: 1.6;
  color: #333;
}

/* Les images ne dépassent jamais leur conteneur */
img,
picture,
video {
  max-width: 100%;
  height: auto;
  display: block;
}

/* Les liens héritent de la couleur du texte */
a {
  color: inherit;
  text-decoration: none;
}

/* Les boutons ressemblent à des boutons */
button {
  font-family: inherit;
  cursor: pointer;
}

/* Les listes non stylées (à activer si besoin) */
ul[class],
ol[class] {
  list-style: none;
  padding: 0;
}
Ce reset est le tien Il est minimal et lisible. Pas besoin de resets obscurs trouvés en ligne. Ces quelques lignes couvrent 90 % des cas. Tu peux le recopier tel quel dans chaque projet.
