Comment marche le web ?

Avant d'écrire une seule ligne de code, il faut comprendre ce qui se passe quand on ouvre un site. Une fois que tu as cette image en tête, tout le reste devient logique.

1 Que se passe-t-il quand tu ouvres un site ?

Tu tapes github.com dans ton navigateur. Une seconde plus tard, une page apparaît. Magique ? Pas du tout. C'est juste un voyage qui se répète des milliards de fois par jour.

Imagine que tu commandes un plat au restaurant. Tu ne vas pas en cuisine voir le cuisinier : tu donnes ta commande à un serveur, il la transmet, la cuisine prépare, et ton plat arrive. Le web fonctionne exactement pareil.

Ton navigateur envoie une demande (on dit une requête). Un ordinateur très puissant, appelé serveur, la reçoit, prépare une réponse, et la renvoie. Ton navigateur affiche la page. C'est tout. Le web, c'est ça : des demandes et des réponses.

2 Les 3 rôles du web

👤

Le visiteur

C'est toi. Tu cliques, tu tapes une adresse, tu remplis un formulaire. Ton navigateur traduit tout ça en demandes.

🌐

Le navigateur

Chrome, Firefox, Safari… C'est le traducteur. Il transforme le code qu'on lui envoie en une page visuelle.

🖥️

Le serveur

Un ordinateur allumé en permanence. Il stocke les fichiers d'un site et les envoie quand on les demande.

À retenir Quand tu « visites un site », tu ne vois en réalité jamais le serveur. Tu vois des fichiers (HTML, CSS, JS, images) que le serveur t'a envoyés, et que ton navigateur assemble.

3 Les 3 langages du web

Un site, c'est trois langages qui travaillent ensemble. Chacun a un rôle précis. Ne les confonds jamais, c'est la base de tout.

HTML

Le contenu · La structure

Décrit ce qu'il y a sur la page : un titre, un paragraphe, une image, un bouton. C'est le squelette.

CSS

L'apparence · Le style

Décide à quoi ça ressemble : couleurs, tailles, espacements, animations. C'est la décoration.

JavaScript

Le comportement · L'interaction

Rend la page vivante : réagit aux clics, calcule, modifie le contenu. C'est le cerveau.

🍽️ L'analogie du restaurant

  • HTML = la carte du restaurant. Elle liste les plats : entrée, plat, dessert. Elle décrit ce qui existe.
  • CSS = la présentation du plat. Comment il est dressé dans l'assiette, les couleurs, la vaisselle. C'est l'apparence.
  • JavaScript = le serveur qui s'anime. Il apporte le plat, retire les assiettes, propose le dessert. C'est l'action.
La formule magique HTML = quoi · CSS = comment ça se présente · JS = ce qui se passe. Répète-la, tu vas la réutiliser tout le temps.

4 Le voyage d'une page, étape par étape

Quand tu tapes une adresse, voici ce qui se passe en une fraction de seconde :

  1. Tu tapes une adresse (une URL). Exemple : github.com.
  2. Ton navigateur cherche le serveur qui héberge ce site. Il demande l'adresse exacte (l'IP) à un annuaire géant appelé DNS.
  3. Il envoie une requête à ce serveur : « donne-moi la page d'accueil ».
  4. Le serveur répond en envoyant les fichiers : HTML, CSS, JS, images.
  5. Ton navigateur assemble le tout et affiche la page. C'est ce que tu vois à l'écran.
Tu n'as pas besoin de tout retenir Retiens juste : demande → serveur → réponse → affichage. Le reste, tu le verras quand on fera du backend.

5 Et toi, dans tout ça ?

Ton métier, en tant que développeur web, c'est d'écrire les fichiers que le serveur va envoyer. Tu n'as pas besoin de gérer des serveurs pour commencer : on écrira des fichiers sur ton ordinateur, on les ouvrira dans ton navigateur, et ça marchera tout de suite.

Le serveur, on s'en occupera plus tard. Aujourd'hui, tu écris. Le navigateur lit.

Un secret bien gardé Tu peux voir le code de n'importe quel site que tu visites. Fais un clic droit sur une page → « Afficher le code source ». Ce que tu vois là, c'est le HTML + CSS + JS que le serveur a envoyé au navigateur. C'est exactement ce que tu vas apprendre à écrire.
