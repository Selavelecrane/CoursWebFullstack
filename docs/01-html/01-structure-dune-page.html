Module 1 · HTML

Structure d'une page

Toute page HTML du monde a la même structure de base. Une fois que tu la connais, tu peux reconnaître n'importe quel site. On va la décortiquer ligne par ligne, et voir où va quoi.

1 Une page, c'est une poupée russe

Souviens-toi du chapitre précédent : une page HTML est faite de balises qui s'emboîtent. Une balise contient d'autres balises, qui en contiennent d'autres, etc. Exactement comme des poupées russes.

<html> la boîte de tout
<head> informations invisibles
<title>…</title> titre de l'onglet
<body> tout ce qui s'affiche
<h1>…</h1> titre visible
<p>…</p> paragraphe
À retenir <html> contient <head> et <body>. Le head, c'est ce qu'on ne voit pas. Le body, c'est ce qu'on voit.

2 Le squelette minimal

Voici la plus petite page HTML valide possible. Neuf lignes. Tu peux la copier telle quelle à chaque nouveau projet. 

<!DOCTYPE html>
<html lang="fr">
<head>
  <meta charset="UTF-8">
  <title>Titre de l'onglet</title>
</head>
<body>

  <!-- Le contenu visible va ici -->

</body>
</html>
ma-page.html

(page vide — rien n'est encore écrit dans le body)

Le navigateur affiche une page blanche : c'est normal, on n'a rien mis dans le body.

3 Chaque ligne, expliquée

Reprenons le squelette, ligne par ligne. Aucune n'est là par hasard.

<!DOCTYPE html>

La déclaration de type. Elle dit au navigateur : « Ceci est une page HTML moderne ». Toujours la première ligne. Elle n'a pas de balise fermante.

<html lang="fr">

La racine. Tout est dedans. L'attribut lang="fr" indique la langue de la page. Utile pour les moteurs de recherche et la synthèse vocale.

<head>

La tête. Contient les informations sur la page : son titre, son encodage, ses styles, etc. Rien d'ici ne s'affiche directement à l'écran.

<meta charset="UTF-8">

L'encodage des caractères. Sans cette ligne, les accents (é, à, ç) s'affichent comme des symboles bizarres. À mettre toujours, en premier dans le head.

<title>…</title>

Le titre de l'onglet. C'est ce qui s'affiche dans l'onglet du navigateur et dans les résultats Google. Change-le à chaque page.

<body>

Le corps. Tout ce que tu vois à l'écran est ici : textes, images, boutons, tout. C'est la partie qu'on va remplir pendant tout le cours.

<!-- commentaire -->

Un commentaire. Invisible dans le navigateur. Sert à laisser des notes à toi-même ou à d'autres développeurs. Le navigateur les ignore.

4 L'indentation : range ton code

Tu remarques que certaines lignes sont décalées vers la droite. C'est l'indentation. Elle n'est pas obligatoire pour le navigateur, mais elle rend ton code lisible.

Compare les deux versions : même code, mais l'un est impossible à lire.

❌ Sans indentation
<html>
<head>
<title>Ma page</title>
</head>
<body>
<h1>Salut</h1>
</body>
</html>
✅ Avec indentation
<html>
  <head>
    <title>Ma page</title>
  </head>
  <body>
    <h1>Salut</h1>
  </body>
</html>
Astuce VS Code Pas besoin de ranger l'indentation à la main. Sélectionne tout (Ctrl + A), puis ouvre la palette de commandes avec Ctrl + Shift + P et tape Format Document. Ton code se range automatiquement.

Encore mieux : installe l'extension Prettier et active l'option Format On Save. À chaque sauvegarde, ton code sera rangé sans que tu y penses.

5 Deux pièges classiques

Piège n°1 : oublier la balise fermante.

Si tu ouvres une balise et que tu ne la fermes pas, le navigateur essaie de deviner où elle se termine. Résultat : ta page s'affiche bizarrement. Chaque ouverture doit avoir sa fermeture. 

<!-- ❌ Mauvais -->
<p>Bonjour, je suis un paragraphe.

<!-- ✅ Bon -->
<p>Bonjour, je suis un paragraphe.</p>

Piège n°2 : croiser les balises.

Les balises doivent s'emboîter proprement. Si tu ouvres A puis B, tu dois fermer B puis A. Comme des parenthèses en maths. 

<!-- ❌ Mauvais : les balises se croisent -->
<p>Un texte <strong>en gras</p></strong>

<!-- ✅ Bon : les balises s'emboîtent -->
<p>Un texte <strong>en gras</strong></p>
Comment repérer une erreur ? Si ta page s'affiche bizarrement, ou si un style ne s'applique pas comme prévu, la première chose à vérifier, c'est qu'il n'y a pas une balise non fermée ou mal emboîtée. C'est l'erreur n°1 des débutants.

6 À toi de jouer

Crée un nouveau fichier structure.html dans ton dossier 01-html, et écris de mémoire le squelette complet d'une page. Ne regarde pas l'exemple ci-dessus !

Ouvre VS Code dans ton dossier cours-web

Crée le dossier 01-html s'il n'existe pas.

Crée un fichier structure.html

Clic droit sur 01-html → New File.

Écris le squelette de mémoire

Commence par <!DOCTYPE html>, ouvre <html>, mets le <head> avec charset et title, puis le <body> vide.

Vérifie avec la solution

Compare avec le squelette du point 2. Une ligne oubliée ? Corrige.

Répète l'exercice deux ou trois fois en effaçant ton fichier à chaque fois. Tu verras qu'après trois essais, tu le connaîtras par cœur. C'est le genre de chose qu'on tape tous les jours en tant que développeur.

🎯 Défi — Ton modèle de départ

Crée un fichier modele.html dans ton dossier 01-html. Ce fichier servira de modèle pour tous tes futurs projets HTML.

  • Écris le squelette complet.
  • Dans le <title>, mets Mon site.
  • Dans le <body>, ajoute un <h1> avec Bienvenue et un <p> avec Ceci est mon modèle de départ.
  • Ajoute un commentaire au-dessus du <h1> : <!-- Contenu principal -->.
  • Sauvegarde, ouvre avec Live Server, vérifie l'affichage.

💡 Garde ce fichier. Chaque fois que tu commenceras un nouveau projet HTML, tu pourras le dupliquer et partir de là.
