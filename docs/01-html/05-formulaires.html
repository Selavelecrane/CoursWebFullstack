Formulaires — les bases

Un formulaire, c'est ce qui transforme un site passif en site interactif : inscription, contact, recherche, connexion… C'est aussi le pont vers le backend (le PHP qu'on verra plus tard). On commence ici par le squelette et les champs de base.

1 À quoi sert un formulaire ?

Tout ce que tu fais sur le web qui « envoie » quelque chose passe par un formulaire : te connecter, créer un compte, écrire un commentaire, chercher une vidéo, valider une commande…

Un formulaire, c'est une zone de saisie dans laquelle l'utilisateur écrit ou choisit des choses. Quand il clique sur le bouton d'envoi, les données partent vers un serveur pour être traitées.

Le trajet des données Utilisateur → remplit le formulaire → clique « Envoyer » → les données voyagent → serveur les reçoit → traite (stocke, vérifie, répond).

Nous, on s'occupe aujourd'hui de la partie visible : le formulaire. Le serveur, ce sera pour plus tard.

2 Le squelette : <form>

Tous les champs d'un formulaire sont enveloppés dans une balise <form>. Elle indique au navigateur : « ceci est un formulaire ».

<form>

Le conteneur. Contient tous les champs et le bouton d'envoi.

action="..."

Vers où envoyer les données (l'adresse d'un script serveur). On peut l'omettre pour l'instant.

method="..."

Comment envoyer (GET ou POST). On verra ça plus tard aussi.

<form>
  <!-- Tous les champs vont ici -->
</form>

Un formulaire vide, c'est… vide

Rien à voir pour l'instant : on n'a mis aucun champ à l'intérieur.

À retenir La balise <form> ne s'affiche pas à l'écran. C'est juste une enveloppe invisible qui dit au navigateur « tout ce qui est dedans fait partie d'un même formulaire ».

3 Le champ de texte : <input>

La balise <input> est auto-fermante et surtout très polyvalente : son comportement change complètement selon la valeur de son attribut type.

Le type le plus courant est type="text" — un champ texte simple. 

<form>
  <input type="text" name="prenom">
</form>

Clique dedans : tu peux taper du texte.

Un <input> a besoin de deux attributs obligatoires en pratique :

type="..."

Quel genre de champ c'est (texte, email, mot de passe, case à cocher…).

name="..."

Le nom du champ. C'est crucial : quand le formulaire est envoyé au serveur, chaque donnée est étiquetée par son name. Sans name, la donnée est perdue.

L'attribut name, c'est sacré Un input sans name n'envoie rien. C'est l'erreur n°1 quand un formulaire « ne marche pas ». Prends l'habitude : chaque champ a un name.

4 Les types d'input à connaître

Voici les types les plus utilisés. Le type change l'apparence du champ (clavier adapté sur mobile, masquage pour les mots de passe, validation automatique…).

Type Ce qu'il fait
text Champ texte simple (le plus courant).
email Vérifie que ça ressemble à un email. Clavier adapté sur mobile.
password Masque la saisie avec des ••••.
number N'accepte que des chiffres. Flèches +/- sur certains navigateurs.
tel Numéro de téléphone. Clavier numérique sur mobile.
url Vérifie que c'est une URL valide.
search Champ de recherche (peut avoir une croix pour effacer).
date Sélecteur de date (calendrier).
color Sélecteur de couleur.
file Bouton pour choisir un fichier à envoyer. 
<form>
  <input type="text"     name="pseudo">
  <input type="email"    name="email">
  <input type="password" name="motdepasse">
  <input type="number"   name="age">
  <input type="date"     name="naissance">
  <input type="color"    name="couleur">
</form>
Pourquoi c'est utile ? Utiliser type="email" plutôt que type="text" pour un email :
  • Le navigateur vérifie automatiquement le format (truc@domaine).
  • Sur mobile, le clavier affiche la touche @ en direct.
  • C'est plus accessible (un lecteur d'écran comprend le rôle du champ).

5 <label> : le meilleur ami du champ

Un champ sans étiquette, c'est un formulaire muet. L'utilisateur doit deviner ce qu'on attend. La balise <label> sert exactement à ça : associer un texte descriptif à un champ.

Il y a deux façons de faire le lien entre un label et un input :

for="..." + id="..."

Méthode classique. Le for du label doit correspondre à l'id du champ. Un id doit être unique sur la page.

<label>…<input>…</label>

Méthode par enveloppement. L'input est dans le label. Plus simple, mais moins flexible à styliser. 

<!-- Méthode 1 : for + id -->
<label for="prenom">Prénom</label>
<input type="text" id="prenom" name="prenom">

<!-- Méthode 2 : enveloppement -->
<label>
  Email
  <input type="email" name="email">
</label>
Le test magique Clique sur le mot « Prénom » dans la démo ci-dessus. Le curseur saute automatiquement dans le champ. C'est ça, un label bien fait. C'est aussi ce qui permet à un lecteur d'écran d'annoncer « Prénom, champ texte ».

6 placeholder : un indice temporaire

Le placeholder affiche un texte grisé à l'intérieur du champ tant que l'utilisateur n'a rien tapé. Ça aide à donner un exemple. 

<input type="email"
       name="email"
       placeholder="ton.email@exemple.com">
Piège classique Le placeholder ne remplace PAS un <label>. Il disparaît dès que l'utilisateur tape, et n'est pas lu par tous les lecteurs d'écran. Un bon formulaire a toujours un label, et parfois un placeholder en bonus.

7 Le bouton d'envoi

Un formulaire sans bouton, c'est une porte sans poignée. Deux options pour créer un bouton d'envoi :

✅ Recommandé
<button type="submit">Envoyer</button>
➕ Ancienne méthode
<input type="submit" value="Envoyer">

Les deux fonctionnent, mais la balise <button> est préférée parce qu'elle :

  • peut contenir du HTML (une icône, une image, un emoji…) ;
  • a un rôle explicite dans le HTML sémantique.
<form>
  <label for="pseudo">Pseudo</label>
  <input type="text" id="pseudo" name="pseudo">

  <button type="submit">S'inscrire</button>
</form>

Le clic déclenche submit — l'envoi au serveur (qu'on fera plus tard).

type="submit", c'est important Le type du <button> peut être :
  • submit → envoie le formulaire (par défaut)
  • button → ne fait rien tout seul (utile avec JavaScript)
  • reset → efface tous les champs du formulaire

8 Premier formulaire complet

Assemblons tout ce qu'on a vu dans un formulaire simple, mais bien fait. 

<form>
  <h3>Créer un compte</h3>

  <label for="pseudo">Pseudo</label>
  <input type="text"
         id="pseudo"
         name="pseudo"
         placeholder="ton pseudo">

  <label for="email">Email</label>
  <input type="email"
         id="email"
         name="email"
         placeholder="ton.email@exemple.com">

  <label for="password">Mot de passe</label>
  <input type="password"
         id="password"
         name="password">

  <button type="submit">Créer mon compte</button>
</form>

Créer un compte

Tu viens d'écrire un vrai formulaire C'est exactement la structure que tu retrouves sur n'importe quel site (Twitter, Instagram, Amazon…). Les champs sont différents, la logique est la même.

🎯 Défi — Ta page d'inscription

Crée un fichier inscription.html dans ton dossier 01-html, avec :

  • Un <h1> : Rejoins l'aventure
  • Un <p> de présentation.
  • Un formulaire contenant :
    • Un champ pseudo (type text) avec un label et un placeholder.
    • Un champ email (type email) avec un label et un placeholder.
    • Un champ mot de passe (type password) avec un label.
    • Un champ date de naissance (type date) avec un label.
    • Un bouton « Créer mon compte ».

💡 Chaque champ doit avoir : un type, un id, un name, et un <label for="..."> correspondant. Vérifie en cliquant sur chaque label : le curseur doit sauter dans le champ.
